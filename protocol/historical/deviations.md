# Protocol deviations and amendments

For each entry below, chronology is stated relative to the outcome-bearing data of the affected branch. Some amendments occurred after results from other, non-affected branches were already available; therefore this log does not claim that the entire project remained outcome-blind. Each entry explicitly records what outcome-bearing data, if any, had been inspected for the affected analysis.

## 2026-08-18 — SynGO source downgraded to sensitivity-only

- Triggering evidence: the SynGO portal documentation identified release 1.3 (2025), but its official bulk-download endpoint could not be retrieved reproducibly from the analysis environment. EMBL–EBI QuickGO did provide a complete, paginated export of 26,133 annotations with `assignedBy=SynGO`.
- Original rule: SynGO was listed as a primary synaptic ontology collection with an unspecified release.
- Revised rule: retain only direct mammalian QuickGO annotations assigned by SynGO, map mouse and rat annotations to human through the frozen strict one-to-one orthology table, and use the result as a sensitivity analysis. It is not eligible to satisfy the candidate gate and must not be described as the SynGO portal release 1.3 bulk dataset.
- Affected analyses: synaptic ontology sensitivity analyses only.
- Outcome-bearing data inspected: no.
- Interpretive consequence: a candidate cannot be created, upgraded, or rejected solely by this proxy collection.

## 2026-08-18 — Cross-species mapping source changed to NCBI Datasets REST gene groups

- Triggering evidence: live Ensembl/OmniPath mapping failed reproducibly, while the monolithic NCBI `gene_orthologs.gz` transfer was incomplete and could have been silently mistaken for a valid concatenated gzip member. The official NCBI Datasets REST API supplied complete protein-coding gene-report pagination for human, mouse, and rat with API version 18.35.0.
- Original rule: use Ensembl one-to-one orthologs.
- Revised rule: join species-specific NCBI protein-coding reports on `Gene Group Identifier`, require `Gene Group Method = NCBI Ortholog`, and retain only groups containing exactly one gene in each species being compared. The API returned 2 empty human and 1 empty rat gene objects among its official report totals; these identifier-free reports are retained in provenance counts but cannot enter a mapping.
- Affected analyses: every cross-species gene-level map, the rat DoRothEA derivation, and the QuickGO–SynGO mammalian sensitivity set.
- Outcome-bearing data inspected: no.
- Interpretive consequence: gene-level transfer is deliberately conservative; pathway- or regulon-level effects remain the primary cross-species comparison object.

## 2026-08-18 — Matrisome source changed from mixed identifiers to official master lists

- Triggering evidence: the MatrisomeAnalyzeR `.rda` combines gene symbols, synonyms, database identifiers, and protein identifiers in one `gene` column. Intersecting that column with current symbol keys produced false symbol classifications. The Matrisome Portal exposes official rev. 2014 master lists with a dedicated `Gene Symbol` column and stated totals of 1,027 human and 1,110 mouse genes.
- Original rule: use a pending MatrisomeDB release for the secondary ECM branch.
- Revised rule: use the official portal master lists; preserve the source symbol and update it only when a current AnnotationDbi alias resolves uniquely. Ambiguous and unresolved symbols are flagged rather than forced.
- Affected analyses: passive-tissue/ECM secondary branch only.
- Outcome-bearing data inspected: no.
- Interpretive consequence: the ECM branch remains secondary and cannot substitute for direct evidence about post-stroke spasticity.

## 2026-08-18 — Local RNA-seq primary aligner changed from STAR to Rsubread Subjunc

- Triggering evidence: the frozen Windows analysis runtime has no native STAR or Salmon executable, no installed WSL/container runtime, and the configured cloud SSH endpoint was unavailable. Rsubread 2.26.0 installed successfully in the isolated R 4.6.1 environment and passed an end-to-end x86_64 Windows smoke test (split-index construction, Subjunc alignment of 1,000 reads, and 90.6% mapping).
- Original rule: adapter/quality assessment, strandedness inference, STAR two-pass alignment and gene counting were primary; Salmon was a sensitivity analysis.
- Revised rule: use checksum-locked NCBI RefSeq genomes/annotations, split gapped Rsubread indexes, Subjunc alignment, and featureCounts exon-to-`gene_id` aggregation as the local primary workflow. Retain unstranded/forward/reverse assignment diagnostics. Select a stranded mode only when it is dominant in at least 80% of libraries, its median assigned count is at least 80% of unstranded assignment, and the median minor/dominant ratio is at most 0.20; otherwise use unstranded counts. Apply this rule without outcome labels. STAR plus featureCounts and Salmon remain pre-specified sensitivity analyses if a version-locked Linux/cloud runtime becomes available; unavailable methods are labelled not run and agreement is not imputed.
- Affected datasets/analyses: raw reprocessing of GSE128623 and mandatory corrected-rat reprocessing of GSE205906; the GSE205906 quantification multiverse.
- Outcome-bearing data inspected: no expression counts, contrasts, pathways, programs, or candidate results from either dataset had been inspected. Only repository metadata, file sizes, reference headers, and a synthetic Rsubread smoke test were examined.
- Interpretive consequence: the primary gene-count inference remains alignment-based and annotation-locked, but cross-aligner/pseudoalignment robustness cannot be claimed unless the cloud sensitivity branch is actually executed. This does not relax the independent biological-library unit, reference-identity stop rule, multiple-testing control, or candidate gate.

## 2026-08-18T09:43:11+08:00 — Parallel HTTPS range transport amendment

- Triggering evidence: the first production ENA FASTQ transfer used one system `curl` connection and averaged approximately 0.7 MiB/s, with pronounced short-term variation. The official HTTPS endpoint advertised byte-range support. At amendment time only the first 144,383,745 contiguous bytes of the first expected 1,804,010,763-byte FASTQ were present; no complete FASTQ, species-screen result, alignment, count matrix, expression contrast, program result, or gate result from GSE205906 existed.
- Original implementation: use a single resumable `curl --continue-at -` request for each checksum-locked ENA URL.
- Revised implementation: use the same system `curl` executable to request up to eight non-overlapping HTTPS byte ranges. Each child request must exit successfully and produce exactly its specified length; the destination must remain unchanged during transfer; ranges are appended in ordinal byte order; and the production driver then applies the unchanged frozen whole-file byte count and ENA MD5 before FastQC or any biological processing. Deterministic temporary segment artifacts are deleted only after successful append; failures retain evidence and stop. The separately tested aria2 binary could not establish DNS/socket connectivity on this host and is not part of the formal workflow.
- Affected datasets/analyses: transport only for future FASTQ downloads in GSE205906 and GSE128623. URLs, samples, biological units, references, QC, species thresholds, aligner, counting, contrasts, multiple-testing families, gates, and claim ceilings are unchanged.
- Outcome-bearing data inspected: no affected-branch biological outcome. Only transport speed, HTTP headers, the incomplete byte-prefix length, source code, and transfer-layer diagnostics were inspected.
- Interpretive consequence: this branch-specific pre-outcome engineering amendment shortens wall time without changing data identity. Acceptance remains fail-closed on the official whole-file bytes and MD5; a segmented transfer cannot enter analysis merely because every child request returned success. The project remains not publicly preregistered.

## 2026-08-18T10:08:11+08:00 — Removal of invalid native-exit-code guard after PowerShell child script

- Triggering evidence: after the segmented downloader successfully assembled the second FASTQ to its exact frozen byte count, the parent driver stopped because strict mode could not retrieve `$LASTEXITCODE`. That variable is defined by native executable invocation, whereas the parent had invoked a PowerShell child script whose internal native processes were already checked and whose exceptions propagate under the parent's stop-on-error policy. Independent read-only verification then showed both completed FASTQs matched their frozen ENA whole-file byte counts and MD5 values. No FastQC, species screen, alignment, count, or biological outcome had run.
- Original implementation: after invoking `download_https_segmented.ps1`, additionally require `$LASTEXITCODE -eq 0` in the parent.
- Revised implementation: remove only that invalid parent-side native-exit-code check. The child script still throws on any failed range, missing part, byte-count mismatch, destination mutation, or final-size mismatch; an exception propagates and stops the parent. The parent still independently enforces frozen whole-file byte count and ENA MD5 before downstream processing. The machine contract now verifies that `$LASTEXITCODE` is not used in the segmented-child invocation block.
- Affected datasets/analyses: download orchestration for GSE205906 and GSE128623 only. No sample, URL, checksum, QC criterion, reference, model, threshold, gate, or claim changed.
- Outcome-bearing data inspected: no. Only transfer completion, frozen size/MD5 identity, the PowerShell error, and source code were inspected.
- Interpretive consequence: this is a pre-biological-processing implementation correction. It removes a redundant, type-inappropriate guard without weakening the actual fail-closed conditions. The project remains not publicly preregistered.
